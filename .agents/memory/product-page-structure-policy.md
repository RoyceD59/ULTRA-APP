name: Product-page structure
description: Owner's intended layered product-page presentation and publication scope
---

The user wants the explicitly layered product-page structure to be visible in
publication on both web and Expo. The supplied Ultra Clear Product Pages HTML
is the content/layout reference, not a request for a simplified redesign.
Preserve each category's authored schema across browsers and Expo; a generic
reduced product layout is not a substitute.

**Why:** The user reported that published pages lacked information and
categorization despite the product-page design already having those layers.

**How to apply:** Preserve authored benefits, suitability, evidence and limits,
package/setup, ownership costs, service, selection review, questions and
specifications, with grouped products and separate replacement navigation.
Check the selected publication source as well as development; release metadata
alone does not prove that the visible published page matches the reference.

Typecheck a transferred UI inside the frozen release, not only in the current
working tree.

**Why:** Current UI code can depend on newer shared contracts or instrumentation
that the frozen parent does not contain, even when the working-tree check passes.

**How to apply:** Reconcile with the release's existing contracts or include only
the necessary reviewed prerequisites. Do not copy unrelated newer modules just
to make the frozen overlay compile.

ProjectHub must support installation-video uploads for each product alongside
its images, with the clip available to the shared web and Expo product page.
The owner requested two video slots per product.

**Why:** The owner explicitly requested per-product installation videos.

**How to apply:** Keep clips associated with the individual product. The separate
three-product photo-activation approval does not limit which products can have
installation-video management; draft product publication restrictions remain.
